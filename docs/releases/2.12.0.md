# v2.12.0 — Front-end Security Architecture

This release hardens the client-side security model: every page now runs under `require-trusted-types-for 'script'` with a Trusted Types policy allowlist that is **computed automatically at build time** from the actual built JavaScript, and page responses gain cross-origin isolation headers (COOP/CORP). The architecture is documented in [Front-end Security Architecture](docs/fe-security.md), with the bootstrap design details in [Trusted Types Bootstrap Design](docs/trusted-types-bootstrap-design.md).

## New

- **Trusted Types enforcement on every page** — the CSP meta now carries `require-trusted-types-for 'script'` and a `trusted-types` policy allowlist. Plain strings can no longer execute through injection sinks (`innerHTML`, `<script src>`, Workers): untrusted values are escaped by the reserved `default` policy, and script URLs must be same-origin.
- **Shared bootstrap package** — policy registration is delegated to [`@localnerve/trusted-types-bootstrap`](https://www.npmjs.com/package/@localnerve/trusted-types-bootstrap) (1.0.x), inlined as the first script on every page (~4 KB). It registers:
  - `default` — the reserved policy: escaping `createHTML` (industry-standard 6-char escape, byte-identical to `he.escape`) and same-origin-only `createScriptURL`. Deliberately **no** `createScript` hook — `eval()`/`new Function()` remain blocked by CSP.
  - `jam-app-static` — pass-through policy for static, author-controlled markup only (e.g., the home page's no-data placeholder). Never use it for user-influenced data.
  - a passthrough shim for browsers without Trusted Types (e.g., Firefox < 148), so those browsers ignore `require-trusted-types-for` and nothing throws.
- **Build-time policy audit** — [`@localnerve/trusted-types-rules`](https://www.npmjs.com/package/@localnerve/trusted-types-rules) (1.0.x) scans every built JS file (app bundles, service worker, and web component bundles) for injection sinks and `createPolicy` registrations — surviving minification via AST + text heuristics — then rewrites the single-word `trusted-types default` placeholder in the page template with the computed directive (e.g., `trusted-types default jam-app-static editable-object`). Component-registered policies like `editable-object` are detected automatically; app-level names are passed explicitly since their registration lives in node_modules. The build logs a sink/component/directive report and warns when a required hook is missing.
- **Cross-origin isolation baseline** — page responses now send `Cross-Origin-Opener-Policy: same-origin` (severs the `window.opener` link; tabnabbing / cross-site probing) and `Cross-Origin-Resource-Policy: same-site` (keeps our resources out of other origins' processes). Assets intentionally carry neither.
- **Colorized build logger** — a shared `log(owner, message)` helper in the build utilities gives the pipeline consistent, timestamped, colorized output (used by the audit report above).

## Changed

- **`frame-ancestors` removed from the CSP meta tag** — it is not a valid meta-only directive per spec; clickjacking protection already ships as the `Content-Security-Policy: frame-ancestors 'self'` response header on page routes (see 2.11.0).
- **`packages/` is now gitignored** — the trusted-types-rules package moved from a vendored in-repo copy to the published scoped npm dependency, so the local staging directory no longer belongs in version control.

## Security

- `editable-object` bumped to 0.5.x-rc: TT-aware web component that registers its own `editable-object` policy (helper code inlined at its build time — no runtime dependency on the helper package).
- The login greeting sink (`Welcome, ${profile.email}`) runs through the escaping `default` policy — user-influenced data can never render as markup.

## Testing

- New Playwright assertions: COOP/CORP present on page routes, and a dedicated test proving assets do **not** carry page-only security headers (COOP, X-Frame-Options).

## Housekeeping

- `mariadb`, `globals`, `puppeteer`, `@localnerve/sass-asset-functions` minor bumps.
- README links the new Front-end Security Architecture doc; analysis index updated.

## Deployment Notes

- No configuration changes required: the policy directive and inline-script CSP hashes are regenerated automatically on every production build (the inline bootstrap script is hash-verified like every other inline script).
- If a page ever needs a new policy name, register it at runtime (or via the bootstrap config) — the build audit will pick up component-registered names automatically; app-level names must be added to the `policyNames` list in `src/build/html.js`.
