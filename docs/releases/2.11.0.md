# v2.11.0 — Web Specification Baseline

This release closes the gaps found in an audit against [The Website Specification](https://specification.website) and, more importantly, establishes a permanent regression guard for it: a new Playwright suite that tests the full spec baseline the project claims — both the items added here and the ones already satisfied — so conformance does not quietly erode.

## New

- **`/llms.txt`** — a curated Markdown index of the site's public pages, generated at build time from `site-data.json`. Advertised on page routes via the HTTP `Link` header (`rel="llms-text"`) for agents that never parse HTML.
- **Explicit AI-crawler policy in `robots.txt`** — GPTBot, Google-Extended, ClaudeBot, PerplexityBot, and Bytespider are now named and disallowed by default, making the site's indexing policy unambiguous to both search engines and LLM crawlers.

## Security

- **HSTS** (`Strict-Transport-Security: max-age=63072000; includeSubDomains`) is now sent — but only when the app actually serves over TLS. The app detects this via a new `--TLS` argument (implied automatically inside the devcontainer, where Caddy terminates TLS). Plain-HTTP local and testcontainer environments never receive the header, avoiding the browser-lockout that an unconditional HSTS header would cause on first request.
- **`Referrer-Policy: strict-origin-when-cross-origin`** on every response.
- **`Permissions-Policy`** disabling unused powerful features (`camera`, `microphone`, `geolocation`, `payment`, `usb`).
- **Clickjacking protection moved to the response header** — `Content-Security-Policy: frame-ancestors 'self'` is now sent with page routes (the `<meta>` tag cannot carry a working `frame-ancestors` directive per spec; it remains in the template only as documentation of intent).
- **Fingerprinted assets are now cached `immutable`** (`Cache-Control: public, max-age=31536000, immutable`).

## Fixed

- **`/.well-known/security.txt` was never actually served.** The file is generated at build time and advertised in the `Link` header, but `express.static` ignores dot-segment paths by default — so every request 404'd. Static serving now allows dotfiles, and the new test suite asserts on the live response to keep it that way.

## Testing

- **New `page.webspecs.test.js` suite** — 16 tests organized by specification category (Foundations, Performance, Security, SEO, Accessibility, Well-known URIs, Agent Readiness). It covers charset/viewport/lang/title/canonical, no-cache HTML and immutable assets, the full header baseline, CSP policy presence, inline-event-handler absence, robots/sitemap/llms.txt content, landmarks, web manifest installability, security.txt fields, and Link-header discovery.

## Deployment Notes

- The production compose now accepts app arguments through the environment: `.env.proxy` sets `APP_ARGS=--TLS`, so `docker/compose-container.sh proxy` runs the app with HSTS enabled behind the external TLS Caddy proxy. The dev env file is untouched, so `docker/compose-container.sh` (no args) runs without it.
- If you deploy behind a TLS proxy of any kind, start the app with `--TLS` so HSTS is emitted.

## Housekeeping

- `@localnerve/gulp-images` 0.8.x, eslint, puppeteer, and rollup minor bumps.
- Accessibility: logo image in the admin header now carries an `alt` attribute.
- Build documentation updated for the new asset generation (robots.txt, security.txt, sitemaps, llms.txt, manifests).
