# v2.13.0 — node-build-stream Build Pipeline

This release retires **gulp** and runs the entire build pipeline on [node-build-stream](https://github.com/localnerve/node-build-stream) (NBS), one stage at a time in the order they appear in `src/build/index.js`. The motivation is dependency reduction and directness: instead of a task-runner framework with per-tool wrapper plugins, the pipeline is written with plain stream primitives (`series`, `pipeline`, `through`), and the underlying tools — PostCSS, dart-sass, html-minifier-terser — are used directly rather than through their gulp wrappers. The revision stage gets a full rewrite as pure NBS, which also fixes a latent double-fingerprinting bug in the service worker registration script. A stage-level progress narrative makes builds readable instead of silent.

## New

- **NBS runner layer** — `gulpfile.js` renamed to `build.js` (auto-detected by the NBS CLI). It registers `task('build')` and `task('dev-build')`, each body a thunk returning the lazy schedule so nothing starts at import time. The `gulp-run`/`gulp-debug` scripts become `nbs-run`/`nbs-debug`; all public script names (`build`, `build:dev`, …) are unchanged. Dependencies: `node-build-stream@^0.10.5` plus explicit `vinyl@^3.0.1`, so NBS uses real vinyl File objects for the remaining gulp-style plugins.
- **Pipeline swap** — in `src/build/{index,copy,html,images,styles}.js`, every `gulp.src(...).pipe(p)...pipe(gulp.dest(d))` chain becomes `pipeline(src(...), ...transforms..., dest(d))`, with `gulp.series` → NBS `series`. Plugins that are plain object-mode transforms (`@localnerve/csp-hashes`, `@localnerve/gulp-images`) carry over unchanged.
- **Revision stage rewritten as pure NBS** — `src/build/revision.js` no longer uses any gulp plugin (replacing `gulp-rev`, `gulp-rev-rewrite`, `gulp-filter`, and `@localnerve/gulp-rev-delete-original`). It is now three sequential `pipeline(src, through(...), dest)` passes:
  - `assetRevision` — fingerprints every non-html/css asset under `dist/` to `<stem>-<sha256[0:10]><ext>` (matching rollup's `[hash:10]` convention), unlinks the original, and emits `dist/rev-manifest.json`.
  - `cssRevision` — rewrites `url()` refs in css to fingerprinted names, hashes all css files, and merges entries into `rev-manifest.json`.
  - `pageRevision` — rewrites top-level pages using the merged revision + rollup manifests.
- **Direct PostCSS** — a `postcssProcess()` through() transform replaces `gulp-postcss`, running `postcss` + `autoprefixer` directly (mirroring the NBS webapp example). `postcss@^8.5.3` is now an explicit devDependency; autoprefixer targets come from the repo-root `.browserslistrc`.
- **Direct Sass** — the raw `node:stream` Transform in `src/build/styles.js` becomes a `sassCompile()` through() transform: compile via `dartSass.compile`, append the version/buildstamp comment (keeping css unique per build), rename `.scss` → `.css`. Compile errors are thrown and surfaced as NBS FileErrors carrying dart-sass's formatted output (path, line:col, snippet) — clearer than the old `PluginError` + `.on('error')` pattern. Partials (`_*.scss`) are still compiled implicitly via load paths and dropped from output.
- **Direct html-minifier-terser** — a `minifyHtmlFiles()` through() transform replaces `gulp-html-minifier-terser`, using v7's async named `minify` export. Prod behavior is unchanged: minified single-line HTML, sha256 CSP hashes appended, trusted-types directive rewritten.
- **Stage-level build progress logging** — a `stage(name, run)` wrapper in `src/build/index.js` logs `→ name` before each stage and `✓ name` (or `✗ name failed` + rethrow) after, so a production build reads as a narrative: prepare, copy images, images, styles, scripts, assets, rev: assets, rev: css, html templates, rev: pages, service worker, minify html, audit. Stages report counts via counter through() transforms — `copied N files`, `compiled N stylesheet(s)`, `fingerprinted N assets`, `revised N css file(s)`, `rewrote asset refs in N top-level page(s)` (revision counts are prod-only). The Handlebars `debug` helper's raw `console.*` output is routed through the shared colorized `log('templates-debug', …)` helper; no direct `console.*` remains anywhere in `src/build`.

## Changed

- **Uniform rollup output naming** — `rollupNames()` in `src/build/settings.js` now returns `[name]-[hash:10].js` for *all* entries (prod). Previously `sw.reg.js` was a special case with the hash in the middle of the filename; it is now `sw.reg-[hash:10].js`, the same shape as every other rollup output. The sw.custom stage reuses the shared `rollupNames(prod)` instead of its own mid-name-hash pattern (`sw.custom-[hash:10].js`; workbox glob updated to `sw.custom*.js`).
- **`pageRevision` scope expanded** — asset refs are now rewritten in all top-level pages (`*.{html,webmanifest,xml}`), not just HTML, so e.g. icon URLs inside the web manifest resolve to fingerprinted names. The per-page count only increments when a file's content actually changed.
- **Single-pass token replacement** — with double-fingerprinting gone (see Fixed), `replaceAllTokens()` in `revision.js` is back to a single pass; the chained-manifest mapping it previously needed no longer exists.

## Fixed

- **`sw.reg.js` double-fingerprinting** — rollup emitted the registration script as `sw-[hash].reg.js`, but `assetRevision` only recognized hashes trailing the stem (`-[0-9a-f]{10}$`), so it re-hashed the file to `sw-<hash>.reg-<sha>.js`. The resulting two-hop name chain is also what forced the fixpoint loop in `replaceAllTokens()`. With uniform rollup naming, already-fingerprinted files are skipped uniformly: `sw.reg.js` no longer appears in `rev-manifest.json` at all — it lives in `rollup-manifest.json`, and every reference (the `swregjs` meta tag, `importScripts`) is rewritten from there.
- **NBS `series()` thenable-unwrap race** — a `series` item that is an async factory returning a schedule gets auto-awaited by JS's thenable-unwrapping, starting the inner schedule immediately and out of order. `createBuild` now passes thunks for the images/styles stages so their factories run only when the series reaches their slot.

## Testing

- The Lighthouse audit suite writes its JSON report **before** asserting on score thresholds, so a failing audit now still produces a report to inspect (previously a threshold failure skipped report writing entirely).

## Housekeeping

- Removed devDependencies: `gulp`, `gulp-filter`, `gulp-rev`, `gulp-rev-rewrite`, `gulp-postcss`, `gulp-html-minifier-terser`, `@localnerve/gulp-rev-delete-original`, `plugin-error`. Added: `node-build-stream`, `vinyl`, `postcss`, `html-minifier-terser`.
- Dependency bumps across the release range (including the 2.12.3–2.12.6 dependency-release cycle): `express` 5.3.0, Node 24.21 baseline, `typescript` 7 / `schema-dts` 2, `mariadb` 12.3.3, `@localnerve/csp-hashes` 8.0.5, `@localnerve/gulp-images` 0.9.0 (the one remaining gulp plugin), `@localnerve/trusted-types-bootstrap` 1.0.2, `@playwright/test` 1.64.1, `puppeteer` 25.14.x, `rollup` 4.64.7; plus an image-download retry and a new `test:debug:prod` script.
- Documentation updated in the same pass as the code: README and [Static Site Generator](static-site-generator.md) now describe the NBS pipeline.

## Deployment Notes

- No configuration changes required, and build output is behaviorally identical: the fingerprinting convention is unchanged (10-hex content hash matching rollup), `rev-manifest.json` is still emitted, and the stable-URL exclusions (`robots.txt`, `sitemap.xml`, `llms.txt`, `.well-known/*`) are preserved.
- The only observable filename changes in prod output are the service worker scripts: `sw.reg.js` → `sw.reg-[hash].js` and `sw.custom.js` → `sw.custom-[hash].js`. All references to them are manifest-rewritten at build time, so nothing external breaks — but any deployment that hardcodes old SW paths should be redeployed with a fresh build.
- `@localnerve/gulp-images` remains as a plain object-mode transform; full removal of the last gulp plugin is deferred (it would be a larger rewrite of the images stage).
