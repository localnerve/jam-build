# v2.14.0 — Mid-Level Asset Revisioning

This release clarifies the production asset-revision pipeline by naming and simplifying its second stage: **mid-level assets**. All stage 2 revision assets are mid-level assets: files that need revisioning and contain references to assets fingerprinted in stage 1. The category is not limited to CSS; it describes the role an asset plays in the revisioning pipeline.

## New

- **Mid-level asset revisioning** — production builds now run a dedicated `rev: midlevel` stage after regular assets are fingerprinted. It rewrites references to stage 1 filenames inside mid-level assets, fingerprints the updated files, and merges their mappings into `rev-manifest.json`. The supported mid-level files include CSS, `site.webmanifest`, and `browserconfig.xml`.
- **Per-format revision reporting** — the build logs the total number of mid-level files revised, with counts by CSS, XML, and web-manifest extension.

## Changed

- **A shared stage 2 pipeline replaces CSS-only revisioning** — the build no longer describes this step as `rev: css`. Mid-level assets are handled by one stage, making the distinction between first-stage assets and assets that reference them explicit. HTML page references are updated afterward using the combined revision manifest.

## Housekeeping

- Updated a broad set of development dependencies across build, lint, and test tooling, including the Sass asset functions and Trusted Types packages, ESLint, PostCSS, Puppeteer, Rollup, Sass, and Sitemap.

## Deployment Notes

- No configuration changes are required. The additional stage runs in production builds and updates the revision manifest so pages and other assets can refer to the final fingerprinted filenames.
